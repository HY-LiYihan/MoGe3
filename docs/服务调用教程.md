# MoGe-3 TCP 推理服务调用教程

本文档介绍如何启动与调用本地部署的 MoGe-3 单目深度估计 TCP 推理服务，包括协议细节、客户端示例、参数说明与并发/批处理行为。

## 1. 服务简介

服务基于 `MoGe/moge/scripts/serve.py`，架构特点：

- **TCP 自定义帧协议**：所有消息 = `4 字节小端 uint32 长度 + payload`
- **异步架构（asyncio）**：单事件循环处理所有连接，收发与图片解码互不阻塞
- **动态微批处理**：并发请求在一个短收集窗口内按（分辨率、参数、是否带 fov）分组合并，一次 GPU 前向处理多帧，显著提升总吞吐；单客户端请求不等待，无额外延迟
- **OOM 自动降级**：批量推理显存不足时自动拆为逐张推理
- 模型：MoGe-3（默认 ViT-L 权重，支持换 vitg）

输出内容：`depth`（深度图）、`points`（相机空间点图）、`normal`（法线图）、`mask`（有效像素掩码）、`intrinsics`（相机内参）与 FOV。

## 2. 环境准备与启动

使用仓库自带虚拟环境：

```powershell
# 启动服务（默认加载 vitl 权重，监听 0.0.0.0:8317）
D:\MoGe3\MoGe\.venv\Scripts\python.exe D:\MoGe3\MoGe\moge\scripts\serve.py
```

常用启动选项：

| 选项 | 默认值 | 说明 |
|---|---|---|
| `--pretrained` | `D:\MoGe3\checkpoints\moge-3-vitl\model.pt` | 本地 checkpoint 路径或 HuggingFace ID（可换 `moge-3-vitg`） |
| `--host` / `--port` | `0.0.0.0` / `8317` | 监听地址与端口 |
| `--resolution-level` | 9 | 默认推理分辨率级别 0-9（每请求可覆盖） |
| `--refine-steps` | 3 | 默认稀疏 3D 精修步数（每请求可覆盖） |

| `--max-image-px` | 8192×8192 | 输入图片最大像素总数 |

| `--batch-window-ms` | 25 | 并发请求的批收集窗口（毫秒，单连接自动跳过） |

## 3. 通信协议

### 3.1 帧格式

所有消息（双向）统一为长度前缀帧：

```
+---------------------+--------------------+
| uint32 小端长度 (4B) | payload (utf-8/字节) |
+---------------------+--------------------+
```

### 3.2 请求

连接后依次发送两帧：

1. **JSON 头部**：

```json
{
  "image_bytes": 123456,
  "format": "jpg",
  "params": {
    "resolution_level": 9,
    "refine_steps": 3,
    "fov_x": null
  }
}
```

2. **图片原始字节**（jpg/png 编码，长度必须等于 `image_bytes`，上限 64MB）

`params` 三个字段均可省略（使用服务端默认值）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `resolution_level` | int 0-9 | 推理分辨率级别，越高细节越丰富、越慢 |
| `refine_steps` | int ≥0 | 稀疏 3D 精修步数，越多质量越高、越慢 |
| `fov_x` | 度数 (1, 179) | 已知相机水平 FOV 时传入可提升度量精度；批处理时同批请求需全有或全无 |

连接为**长连接**，可循环发送多次请求。

### 3.3 响应消息序列

```
status(received) → status(inferring) → [array 元数据 + 数组帧] × 2~4 → done
```

- `status`：`{"type": "status", "stage": "received|inferring", ...}`
- `array`：先收 JSON 元数据 `{"type": "array", "name": "depth", "dtype": "float32", "shape": [H, W], "compression": "none", "bytes": N}`，随后紧跟一帧数组原始字节
- `done`：包含汇总信息
- 出错时返回 `{"type": "error", "stage": "request|inference", "message": "..."}` 并关闭连接

数组顺序与语义：

| 名称 | dtype | shape | 压缩 | 说明 |
|---|---|---|---|---|
| `depth` | float32 | (H, W) | 无 | 深度（米），无效像素为 inf |
| `points` | float32 | (H, W, 3) | 无 | 相机空间点图，无效像素为 inf |
| `normal` | float32 | (H, W, 3) | 无 | 法线图，无效像素为 0 |
| `mask` | uint8 | (H, W) | zlib | 有效像素为 1 |

`done` 消息字段：

| 字段 | 说明 |
|---|---|
| `width` / `height` | 图片分辨率 |
| `intrinsics` | 3×3 归一化内参 |
| `fov_x` / `fov_y` | 水平/垂直 FOV（度） |
| `elapsed_ms` | 服务端全程耗时（含排队） |
| `infer_ms` | 本批 GPU 推理耗时 |
| `queue_ms` | 排队等待耗时 |
| `batch_size` | 本请求所在批的合并请求数 |

## 4. 客户端调用示例

### 4.1 命令行客户端

```powershell
D:\MoGe3\MoGe\.venv\Scripts\python.exe D:\MoGe3\client_example.py --image 图片路径
# 可选: --host --port --resolution-level --refine-steps --fov-x
```

### 4.2 Python 最小调用（核心 ~40 行）

```python
import json, socket, struct, zlib
import numpy as np

LENGTH_PREFIX = struct.Struct('<I')

def recv_exact(sock, n):
    buf = bytearray()
    while len(buf) < n:
        chunk = sock.recv(n - len(buf))
        if not chunk:
            raise ConnectionError('connection closed')
        buf.extend(chunk)
    return bytes(buf)

def recv_frame(sock):
    (length,) = LENGTH_PREFIX.unpack(recv_exact(sock, 4))
    return recv_exact(sock, length)

def send_frame(sock, payload):
    sock.sendall(LENGTH_PREFIX.pack(len(payload)) + payload)

def moge_infer(sock, image_path: str, params: dict = None):
    image_bytes = open(image_path, 'rb').read()
    header = {'image_bytes': len(image_bytes), 'format': 'jpg', 'params': params or {}}
    send_frame(sock, json.dumps(header).encode('utf-8'))
    send_frame(sock, image_bytes)

    arrays, done = {}, None
    while True:
        msg = json.loads(recv_frame(sock))
        if msg['type'] == 'array':
            payload = recv_frame(sock)
            if msg.get('compression') == 'zlib':
                payload = zlib.decompress(payload)
            arrays[msg['name']] = np.frombuffer(payload, dtype=msg['dtype']).reshape(msg['shape'])
        elif msg['type'] == 'done':
            done = msg
            break
        elif msg['type'] == 'error':
            raise RuntimeError(f"server error at {msg.get('stage')}: {msg.get('message')}")
    return arrays, done

with socket.create_connection(('127.0.0.1', 8317), timeout=120) as sock:
    arrays, done = moge_infer(sock, r'D:\MoGe3\MoGe\example_images\01_HouseIndoor.jpg')
    print(f"depth: {arrays['depth'].shape}, fov_x={done['fov_x']}°, 推理 {done['infer_ms']}ms")

# 长连接可继续调用 moge_infer(sock, ...) 处理后续帧
```

## 5. 并发与批处理行为

- **连接层完全异步**：任意数量客户端可同时连接，图片接收/解码/结果发送并行
- **GPU 推理串行 + 动态批处理**：并发请求在收集窗口内合并为一次前向。批处理要求同批请求分辨率与参数一致，不一致的请求自动分流到下一批
- **延迟-吞吐权衡**：并发下单个请求的延迟略高于单独调用（等待成批 + 批量前向本身更久），但总吞吐显著提升；单客户端无窗口等待，延迟不变
- **显存不足保护**：批推理 OOM 时自动清理缓存并降级为逐张推理，请求仍能完成

实测数据（RTX 4080 Laptop，vitl，fp16，测试视频 3fps 采帧，4 路并发流式推送）：

| 场景 | 旧版（线程+锁串行） | 新版（异步+动态批处理） |
|---|---|---|
| 单次调用延迟（level 9 / refine 3） | ~523 ms | ~538 ms（持平，单连接自动跳过收集窗口） |
| 4 路并发聚合吞吐（level 9） | 2.21 帧/s | 2.21 帧/s（GPU 单帧已饱和，持平） |
| 8 路并发聚合吞吐（level 9） | 2.09 帧/s | ~2.0 帧/s |
| 4 路并发聚合吞吐（level 5） | 2.73 帧/s（关批处理对照） | **3.11 帧/s（+14%）** |
| 4 路平均单请求延迟（level 5） | 1424 ms | **1261 ms（-11%）** |

结论与建议：

- **GPU 有余量时批处理收益明显**：level 5 实测吞吐 +14%、平均延迟 -11%；GPU 越空闲（分辨率级别越低、模型越小、显卡越强），收益越大
- **level 9 的 vitl 在笔记本 GPU 上单帧已吃满 GPU**（B=2 批量耗时 ≈ 2× 单帧），此档位下并发吞吐恒为 ~2 帧/s，瓶颈在 GPU 算力本身；如需提升可降低 `resolution_level` 或减少 `refine_steps`
- **公平性改善**：同批请求几乎同时返回结果，避免旧版"先到先得、后到者多等一整段"的长尾
- **Windows 注意**：批处理过大可能触发 WDDM 显存换页（表现为极慢而非 OOM 报错），12GB 显存默认 `--max-batch-size 2`，显存充裕时可调到 4 以上

## 6. 错误处理与限制

- 请求头缺少 `image_bytes`、图片解码失败、payload 长度不符 → `stage: request` 错误
- 推理阶段异常（含 OOM 降级后仍失败）→ `stage: inference` 错误
- 单帧上限 256MB，请求图片上限 64MB，分辨率上限默认 8192×8192 像素
- `fov_x` 传入后与未传入的请求不会合并到同一批（协议行为不变，仅影响内部批处理分组）
